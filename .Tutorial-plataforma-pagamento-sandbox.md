# Tutorial: testando pagamentos de verdade no sandbox (exemplo: Asaas)

Este guia explica, do zero e sem pressupor que você já mexeu numa plataforma de pagamento, como ligar o CrowdAcadêmico ao **ambiente de testes** de uma plataforma de pagamento e testar o fluxo do dinheiro inteiro: alguém apoia, paga o Pix, a campanha fecha, o dinheiro vai para o pesquisador (ou volta para quem apoiou).

O exemplo é o **Asaas**, que é a plataforma que o sistema usa hoje. As ideias valem para qualquer outra (Mercado Pago, PagBank, Efí, Stripe): só mudam os nomes dos menus.

Siga na ordem. Não pule etapas mesmo que pareçam óbvias.

---

## ⚡ Para abrir o túnel (copie e cole, num terminal só para ele)

```
"C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:3000
```

- Esse é o jeito que **sempre** funciona no cmd. No PowerShell, ponha `& ` na frente.
- Depois de fechar e abrir o VS Code uma vez após a instalação, o curto também funciona: `cloudflared tunnel --url http://localhost:3000`.
- O endereço `https://....trycloudflare.com` **muda a cada vez**: atualize a URL no webhook do Asaas (Parte 7) toda vez que abrir o túnel de novo.
- Junto com ele ficam rodando, cada um no seu terminal: `npm run start:dev` (em `nest/`) e `npm run dev` (em `react/`).

## Parte 0 - em palavras simples: como o dinheiro anda no sistema

1. **Quem apoia contribui.** O sistema pede à plataforma de pagamento uma **cobrança Pix** e mostra o código Pix (o "copia e cola").
2. **A pessoa paga** no aplicativo do banco dela.
3. **A plataforma avisa o sistema** que o Pix foi pago. Esse aviso é o **webhook** (Parte 1). O sistema confere com a plataforma se é verdade e marca a contribuição como paga.
4. **A campanha fecha.**
   - Bateu a meta (ou é flexível): o sistema manda o dinheiro para a **chave Pix do pesquisador** (o **repasse**), descontada a taxa da plataforma.
   - Tudo-ou-nada que não bateu a meta: o sistema **devolve** o dinheiro para quem apoiou (o **estorno**).

Tudo isso roda sozinho, de tempos em tempos (de 5 em 5 minutos, de 15 em 15). Para testar sem esperar, existe a **T5 - Bancada de Pagamento** no Campo de Testes do painel (Parte 10).

### A regra de ouro: a plataforma nunca fica no prejuízo

- O Pix em si é grátis entre pessoas. Mas a **plataforma de pagamento cobra uma tarifa** de quem recebe (o CrowdAcadêmico), por cada Pix recebido.
- Quem paga essa tarifa é **quem apoia, por cima do valor**: contribui R$ 100, paga R$ 100 + tarifa.
- Na devolução do tudo-ou-nada, a pessoa recebe **os R$ 100 inteiros** de volta. A tarifa não volta (a plataforma não devolve a tarifa dela), mas quem apoiou já sabia que ela existia.
- A tarifa **não entra** no valor arrecadado da campanha nem no repasse ao pesquisador.
- O valor da tarifa é o parâmetro **`taxa_pagamento_pix`** (Painel > Parâmetros do Sistema > Financeiro). É só o ponto de partida: o sistema lê a tarifa real do Asaas a cada cobrança e corrige o parâmetro sozinho (Parte 12). **0 = sem tarifa.**

Tarifas do Asaas para Pix (conferir sempre na página de taxas, porque mudam):
- isenção das primeiras transações do mês só vale para Pix por **chave ou QR code estático**. O sistema usa **cobrança pela API (QR dinâmico)**, que normalmente é tarifada sempre;
- período promocional para conta nova: cerca de R$ 0,99 por Pix;
- tarifa padrão: cerca de R$ 1,99 por Pix;
- no sandbox nada é cobrado de verdade.

## Parte 1 - os conceitos, um por um

**Sandbox x produção.** Toda plataforma de pagamento tem dois ambientes separados, com contas, chaves e endereços diferentes:
- **sandbox**: dinheiro de mentira, para testar à vontade;
- **produção**: dinheiro real.
Uma chave de um não funciona no outro.

**Chave de API.** É a "senha" que o sistema usa para falar com a plataforma (criar cobrança, devolver, transferir). Quem tem a chave mexe no dinheiro da conta. Por isso ela fica **só** no arquivo `nest/.env`, que **nunca vai para o Git**. Nunca cole a chave em chat, e-mail, print ou commit. Se vazar, apague-a no painel e gere outra.

**Cliente genérico.** O Asaas exige um "cliente" em toda cobrança. Como as contribuições podem ser anônimas, o sistema usa **um cliente só** para todas.

**Webhook (o aviso).** É o jeito de a plataforma avisar o sistema que algo aconteceu ("o Pix foi pago", "a transferência caiu"). A plataforma faz uma chamada para um **endereço do seu sistema** (por exemplo `https://seu-site.com/pagamento/webhook/asaas`). Sem webhook, o sistema não fica sabendo que o Pix foi pago (até a conferência automática perguntar, bem mais tarde).

**Token do webhook.** Qualquer um poderia chamar aquele endereço fingindo ser a plataforma. Por isso existe uma senha combinada: você inventa um texto longo, coloca no `nest/.env` e cola **o mesmo texto** no cadastro do webhook na plataforma. O sistema só aceita aviso que chegar com esse texto.

**Túnel.** Veja a Parte 2.

**Validação de saque.** Uma proteção extra do Asaas: antes de executar **cada** transferência, ele pergunta ao sistema "esta transferência é sua mesmo?". O sistema só aprova o que bate com um repasse dele (mesmo valor e mesma chave Pix). Assim, mesmo que a chave de API vaze, ninguém consegue tirar dinheiro da conta. Veja a Parte 9.

**Provedor de teste (Fake).** Sem configurar nada, o sistema usa um "provedor de mentira" que vive na memória do Nest. Serve para testar o fluxo sem conta nenhuma (Parte 10). Ele **esquece tudo quando o Nest reinicia**.

## Parte 2 - o túnel: o que é, para que serve e por que é necessário

**O problema.** O webhook é a plataforma (que está na internet) chamando o seu sistema. Mas, no seu computador, o Nest roda em `http://localhost:3000`, e `localhost` quer dizer "este computador aqui". A plataforma, lá na internet, não tem como chegar no seu computador: ele não tem um endereço público (está atrás do roteador da sua casa ou da escola).

**A solução: um túnel.** Um programa que você roda no seu computador abre uma conexão com um serviço na internet e recebe de volta um **endereço público temporário** (tipo `https://palavras-aleatorias.trycloudflare.com`). Tudo que chegar nesse endereço é repassado para o seu `localhost:3000`. É como um "desvio" da internet até o seu computador.

**A plataforma de pagamento tem túnel próprio?** Não. Nenhuma das grandes (Asaas, Mercado Pago, PagBank, Stripe) oferece túnel: elas só sabem **mandar o aviso para um endereço público** que você informar. O túnel é sempre um programa à parte. (A Stripe tem um programa de linha de comando que repassa os avisos dela para o seu computador, mas só serve para a Stripe.)

**E o Supabase, não serve de túnel?** Embora o sistema esteja usando o Supabase como banco e como armazenamento dos arquivos, ele **não tem túnel**. A diferença é **quem chama quem**:
- banco e arquivos: é o **Nest que chama o Supabase**. Sair do seu computador para a internet sempre funciona, por isso nunca precisou de túnel;
- criar cobrança, devolver e transferir: também é o **Nest que chama o Asaas**. Também não precisa de túnel;
- o aviso de pagamento (webhook): é o **Asaas que chama o seu computador**. Entrar da internet no seu computador é o que não funciona sem um endereço público. Só isso precisa de túnel.

O Supabase tem as **Edge Functions** (pequenos códigos rodando na internet, com endereço público), que poderiam receber o aviso. Mas não resolvem: elas também não alcançam o seu computador, e o aviso teria de ser tratado fora do Nest, reescrito. Complicação sem ganho.

**Dá para testar sem túnel?** Dá. O sistema tem a **conferência com o provedor**: de tempos em tempos, ele mesmo pergunta ao Asaas sobre os Pix pendentes (é o Nest chamando, então não precisa de túnel). Para não esperar:
1. Painel > Parâmetros do Sistema: baixe `reconciliacao_limite_minutos` de 30 para 1;
2. pague a cobrança no sandbox;
3. na T5, clique em **Conferir com o provedor**: a contribuição vira "Paga" sem nenhum aviso.

O repasse funciona igual: sem aviso, o sistema consulta o Asaas sozinho depois de alguns minutos. O túnel só é obrigatório para testar **o webhook de verdade** (o caminho que vai rodar em produção) e a **validação de saque** (Parte 9).

**Quais túneis existem.**
- **Cloudflare Tunnel** (`cloudflared`): grátis, **não pede cadastro** no modo rápido. É o que este tutorial usa.
- **ngrok**: muito usado, mas pede cadastro e um token.

**Em produção não precisa de túnel.** Quando o sistema estiver publicado (Render, Railway, etc.), ele já tem um endereço público de verdade. O túnel é só para testar no seu computador.

**Cuidado:** enquanto o túnel está aberto, o seu Nest fica acessível pela internet por aquele endereço. Feche o túnel (Ctrl + C no terminal dele) quando terminar de testar.

## Parte 3 - criar a conta no sandbox

1. Entre em `https://sandbox.asaas.com` e crie a conta (é separada da conta de produção).
2. Depois do cadastro, você cai no painel (`/dashboard/home`).
3. O painel mostra "Banco 461 - Asaas", agência e conta: é a sua conta **dentro do próprio Asaas** (ele também funciona como banco digital). No sandbox, é tudo de mentira. **A integração não usa esses números.**
4. **Cadastre uma chave Pix da conta** (menu **Pix** > minhas chaves; a chave aleatória serve). É por ela que a conta da plataforma **recebe** os Pix de quem apoia. Sem chave, o Asaas recusa toda cobrança Pix com "Você não possui uma chave Pix cadastrada para recebimentos de cobranças via Pix". (No sandbox, o próprio Asaas criou uma chave aleatória sozinho depois da primeira recusa; em produção, cadastre antes.)

## Parte 4 - gerar a chave de API

1. No painel: menu do usuário (ícone de pessoa, no canto de cima) > **Integrações** > aba **Chaves de API** > **Gerar chave de API**.
2. Preencha o formulário:
   - **Nome da chave:** `CrowdAcademico Sandbox` (é só uma etiqueta para você reconhecer).
   - **Data e hora de expiração:** deixe em branco. Se a chave expirar, o sistema para de falar com o Asaas sem avisar.
   - **"Permitir que esta chave execute operações de saque via API":** **marque**. É o que deixa o sistema mandar o repasse por Pix ao pesquisador. Sem isso, o repasse falha.
3. Clique em **Avançar**. O Asaas mostra a chave **uma única vez**: clique em **Copiar** antes de fechar. A chave do sandbox começa com `$aact_hmlg_` (a de produção, com `$aact_prod_`).
4. Abra o `nest/.env` e acrescente no fim, com a chave **entre aspas simples** (o `$` faz parte da chave; sem aspas, algumas ferramentas apagam o começo dela):
   ```
   ASAAS_ENV=sandbox
   ASAAS_API_KEY='$aact_hmlg_...a chave inteira...'
   ```

> Atenção: o Asaas desativa chaves que ficam 3 meses sem uso e apaga de vez depois de 6 meses. Se o sistema começar a dizer que a chave é inválida depois de muito tempo parado, gere outra.

## Parte 5 - criar o cliente genérico

1. No menu da esquerda: **Meus Clientes** > **Clientes** > adicionar cliente.
2. **Nome:** `Apoiador CrowdAcadêmico`.
3. **CPF:** use um CPF **de teste** (o botão de gerar CPF da T1 - Bancada do Pesquisador gera um válido). Não use o seu. Preencha o CPF: o Asaas costuma exigir CPF para gerar cobrança Pix.
4. Se aparecer opção de notificações (e-mail, SMS), **desligue**, para o Asaas não mandar mensagem a cada contribuição.
5. Salve. O **código do cliente** está no fim do endereço da página do cliente: `https://sandbox.asaas.com/customerAccount/show/1234567` quer dizer que o código é `cus_000001234567` (o número, com `cus_` e zeros na frente até ficar com 12 dígitos).
6. Acrescente no `nest/.env`:
   ```
   ASAAS_CUSTOMER_ID=cus_000001234567
   ```
   (com o número do **seu** cliente, claro). Este código não é segredo.

## Parte 6 - abrir o túnel

1. **Instalar (uma vez só).** No PowerShell:
   ```
   winget install --id Cloudflare.cloudflared
   ```
   Depois **feche e abra** o terminal (senão ele não acha o comando novo).
   - Computador que reseta todo dia (escola): baixe o instalador do `cloudflared` na página da Cloudflare e guarde no Drive ou pendrive, como os outros instaladores do `.Tutorial-rodar-projeto.md`.
2. **Abrir.** Num terminal só para ele:
   ```
   cloudflared tunnel --url http://localhost:3000
   ```
   (se o seu Nest roda em outra porta, troque o `3000`).
3. No meio das mensagens, aparece um endereço tipo `https://palavras-aleatorias.trycloudflare.com`. **Deixe esse terminal aberto**: fechar o terminal fecha o túnel.
4. Esse endereço **muda toda vez** que você roda o comando. Quando mudar, atualize a URL no webhook do Asaas (Parte 7).

As mensagens `INF` que o túnel imprime (incluindo "Cannot determine default configuration path" e "does not support loading the system root certificate pool") são normais. Só se preocupe com linhas `ERR`.

**Se aparecer "'cloudflared' não é reconhecido como um comando" (no cmd) ou "O termo 'cloudflared' não é reconhecido" (no PowerShell):**

- **Por quê:** o programa foi instalado, mas o terminal não sabe onde ele está. Cada terminal lê, ao abrir, a lista de pastas onde procurar programas (o "PATH" do Windows). O `winget` acrescentou a pasta do `cloudflared` nessa lista, mas um terminal que já estava aberto continua com a lista velha. Às vezes nem um terminal novo do VS Code resolve, porque ele herda a lista do VS Code, que também estava aberto antes da instalação.
- **Solução definitiva:** fechar o VS Code inteiro e abrir de novo.
- **Solução na hora (sem fechar nada):** chamar o programa pelo caminho completo. O jeito de escrever muda conforme o terminal:
  - no **cmd** (o prompt aparece como `C:\Users\...>`):
    ```
    "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:3000
    ```
  - no **PowerShell** (o prompt aparece como `PS C:\Users\...>`), precisa de um `&` na frente, senão o PowerShell acha que o texto entre aspas é só um texto e não um programa:
    ```
    & "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:3000
    ```
  - para passar do PowerShell para o cmd no mesmo terminal, basta digitar `cmd` e Enter.

## Parte 7 - cadastrar o webhook no Asaas

No painel: **Integrações** > aba **Webhooks** > **Adicionar Webhook**:

- **Nome:** `CrowdAcademico`
- **URL:** o endereço do túnel + `/pagamento/webhook/asaas`. Exemplo: `https://palavras-aleatorias.trycloudflare.com/pagamento/webhook/asaas`
- **E-mail:** o seu (o Asaas avisa se os avisos começarem a falhar)
- **Token de autenticação:** o Asaas já gera um (começa com `whsec_`). **Copie** antes de salvar: ele vai para o `.env` na Parte 8.
- **Versão da API:** v3 (o sistema foi feito para a v3)
- **Tipo de envio:** sequencial
- **Ativo:** sim
- **Eventos:** marque
  - `PAYMENT_CONFIRMED`, `PAYMENT_RECEIVED`, `PAYMENT_OVERDUE`, `PAYMENT_DELETED`, `PAYMENT_REFUNDED`, `PAYMENT_PARTIALLY_REFUNDED`
  - `TRANSFER_DONE`, `TRANSFER_FAILED`, `TRANSFER_CANCELLED`

Outros eventos podem ficar desmarcados: se chegarem, o sistema guarda e ignora.

> O Asaas só considera o aviso entregue quando o sistema responde "200". Se o Nest estiver desligado ou o túnel fechado, os avisos ficam numa fila e, depois de muitas falhas, o Asaas **pausa** o webhook. Se isso acontecer, reative-o na mesma tela depois de arrumar o túnel. A aba **Logs de Webhooks** mostra cada aviso enviado e a resposta.

## Parte 8 - ligar o sistema no sandbox

1. No `nest/.env`, acrescente (com o token copiado na Parte 7):
   ```
   PAYMENT_PROVIDER=asaas
   ASAAS_WEBHOOK_TOKEN=whsec_...
   ```
   Sem `PAYMENT_PROVIDER` (ou com `PAYMENT_PROVIDER=fake`), o sistema usa o provedor de teste da memória, e as linhas `ASAAS_...` ficam guardadas sem efeito.
2. Suba o Nest como sempre (`npm run start:dev`, dentro de `nest/`), num terminal **separado** do túnel. O túnel e o Nest precisam estar ligados ao mesmo tempo.
3. **Se faltar ou estiver errado algo da configuração do Asaas, o Nest se recusa a subir** e mostra uma mensagem listando o que corrigir. Isso é de propósito: com dinheiro, é melhor falhar alto do que descobrir na primeira contribuição.

Resumo do que fica no `nest/.env` (com os seus valores):

```
PAYMENT_PROVIDER=asaas
ASAAS_ENV=sandbox
ASAAS_API_KEY='$aact_hmlg_...'
ASAAS_CUSTOMER_ID=cus_...
ASAAS_WEBHOOK_TOKEN=whsec_...
```

**Como saber se deu certo:** abra no navegador o endereço do túnel + `/health` (exemplo: `https://palavras-aleatorias.trycloudflare.com/health`).
- Apareceu `{"status":"ok","banco":"conectado"}`: túnel, Nest e banco funcionando.
- Página da Cloudflare com **"Error 502 - Bad gateway"** ("Browser: Working", "Cloudflare: Working", "Host: Error"): o túnel está certo, mas **o Nest não está rodando** (ou está em outra porta). Suba o Nest e recarregue a página.

## Parte 9 - validação de saque (OBRIGATÓRIA para o repasse sair)

**Por que é obrigatória:** o Asaas **não executa sozinho** uma transferência nem uma devolução de Pix pedidas pela API. Ela fica parada como "aguardando autorização" até alguém autorizar no painel (com código por SMS ou aplicativo), uma por uma. Com a validação de saque ligada, o Asaas pergunta ao sistema antes de cada transferência, e o sistema responde sozinho: **aprova** a que bate com um repasse dele (mesmo valor e mesma chave Pix do pesquisador) e **recusa** qualquer outra (por exemplo, alguém com a chave de API vazada tentando tirar dinheiro). O mesmo vale para a **devolução** a quem apoiou: o sistema só aprova a de uma contribuição "a devolver", no valor certo. Sem a validação, nenhum repasse e nenhuma devolução sai sem clique. (O Pix que entra, de quem apoia, nunca precisa de autorização.)

Na tela **Integrações** > **Segurança** > **Validação de saque via Webhook**, clique em **Habilitar validação** e preencha:

1. **URL do Webhook:** o endereço do túnel + `/pagamento/webhook/asaas/autorizacao-saque`.
2. **E-mail para notificação de erros:** o seu.
3. **Token de autenticação:** o mesmo `whsec_...` do webhook (Parte 7).
4. As caixas:
   - "Validar também saques via interface": **desmarcada**. Se marcar, todo saque que **você** fizer pelo site ou aplicativo do Asaas também pergunta ao sistema, e o sistema só aprova repasse e devolução: você não conseguiria sacar o dinheiro da própria conta.
   - "Splits de Pagamento": **desmarcada** (o sistema não usa split).
   - **"Ativar autorização de saque para estornos Pix": MARCADA.** Sem ela, cada devolução fica parada no Asaas esperando autorização manual.

Transferência ou devolução criada **antes** de ligar a validação continua precisando da autorização manual, uma vez.

Quando o túnel mudar de endereço, atualize **as duas URLs**: a do webhook (Parte 7) e a desta tela.

"Endereços IP autorizados" (na mesma tela) **não serve para teste com túnel**: o seu endereço muda. Fica para produção, se o servidor tiver IP fixo.

## Parte 10 - testar

### Sem conta nenhuma: o provedor de teste (Fake)

Sem `PAYMENT_PROVIDER` no `.env` (ou com `PAYMENT_PROVIDER=fake`), abra o painel, entre como Admin e vá em **Campo de Testes > T5 - Bancada de Pagamento**:

1. **Gerar Pix:** escolha uma campanha ativa e um valor. Aparece o valor, a tarifa e o total.
2. Na linha da contribuição: **Pagar o Pix** (ou **Fazer o Pix vencer**, ou **Repetir o último aviso**). O aviso passa pelo webhook de verdade, dentro do próprio Nest.
3. **Tarefas automáticas:** "Fechar campanhas vencidas", "Rodar o repasse", "Rodar a devolução" e "Conferir com o provedor" fazem na hora o que o sistema faz de tempos em tempos.
4. Para o repasse sair, o dono da campanha precisa ter chave Pix confirmada: entre como ele ("Entrar como" > Pesquisador), use **Minha chave Pix**, volte para Admin e rode o repasse. Depois, na linha do repasse, **Concluir** ou **Falhar a transferência**.

> O provedor de teste guarda tudo na memória. Se o Nest reiniciar (inclusive o reinício automático ao salvar um arquivo), ele esquece as cobranças: o Pix pendente aparece como "Perdida (o Nest reiniciou)" e só vence sozinho.

### Com o sandbox do Asaas

1. Siga as Partes 3 a 8.
2. Na T5, **Gerar Pix** cria a cobrança de verdade no sandbox (ela aparece no painel do Asaas, em **Cobranças**).
3. **Pagar:** no painel do Asaas, abra a cobrança e use a opção do sandbox de **confirmar/simular o pagamento**. O Asaas manda o aviso pelo túnel e a contribuição vira "Paga" no sistema.
4. As **Tarefas automáticas** da T5 funcionam com o Asaas também. Os botões Pagar, Vencer, Concluir e Falhar são só do provedor de teste: no sandbox, isso é feito no painel do Asaas.

### Testar o repasse ao pesquisador no sandbox

O sandbox **não completa transferência para uma chave Pix qualquer**: a chave de mentira cai num "banco fictício" que recusa, e a transferência termina com **"Pagamento rejeitado pelo PSP do recebedor"**. Isso é do sandbox, não do sistema (e serve para testar o caminho da falha). Para testar o **sucesso**, a documentação do Asaas dá chaves fictícias do Banco Central, em que a transferência é concluída (o dinheiro sai do saldo e não cai em lugar nenhum):

| Chave Pix (e-mail) | Titular | CPF do titular |
|---|---|---|
| `cliente-a00001@pix.bcb.gov.br` | João Silva | 999.911.111-40 |
| `cliente-a00002@pix.bcb.gov.br` | João Silva Silva | 999.922.222-63 |
| `cliente-a00003@pix.bcb.gov.br` | José Silva | 999.933.333-87 |

Como o sistema só aceita a chave se o titular tiver **o CPF do perfil do pesquisador**, o teste é:

1. Antes de tudo, a conta precisa de **saldo** no sandbox: ele vem das cobranças pagas (Parte 10, acima).
2. Admin: troque o CPF do pesquisador para o do titular (ex.: `99991111140`) pela correção de CPF do painel. **Anote o CPF original.**
3. Entre como o pesquisador e cadastre a chave `cliente-a00001@pix.bcb.gov.br` (tipo e-mail). A titularidade deve aparecer **confirmada**.
4. Feche uma campanha dele com contribuição paga (fim do prazo, ou "Encerrar antes do prazo" aprovado pelo admin): o repasse nasce sozinho.
5. Na T5, **Rodar o repasse**. Em cerca de 1 a 2 minutos, o Asaas conclui, o aviso chega, o repasse vira **"Concluído"** e as contribuições, **"Repassada"**.
6. **Volte o CPF original** do pesquisador e a chave dele.

Se o repasse terminar em **"Erro"** (por exemplo, a recusa do banco fictício), ele aparece na tela de **Repasses que pedem atenção** do painel; o admin corrige a causa e usa **Reenfileirar**.

## Parte 11 - problemas comuns

- **O Nest não sobe e fala do Asaas:** leia a mensagem, ela diz o que corrigir. Os mais comuns: chave sem aspas simples (o começo `$aact` some), chave de produção com `ASAAS_ENV=sandbox` (ou o contrário), `ASAAS_CUSTOMER_ID` faltando, `ASAAS_WEBHOOK_TOKEN` com menos de 32 caracteres.
- **Paguei no sandbox e a contribuição continua "Aguardando pagamento":**
  1. o túnel ainda está aberto? (o terminal dele não pode ter sido fechado);
  2. a URL no webhook do Asaas é a do túnel **de agora**? (ela muda a cada vez);
  3. o token no Asaas é igual ao `ASAAS_WEBHOOK_TOKEN` do `.env`?;
  4. a aba **Logs de Webhooks** do Asaas mostra o aviso e a resposta do sistema;
  5. o webhook não está **pausado** por falhas anteriores?
  Mesmo sem aviso, a conferência automática pergunta ao Asaas sobre Pix pendente (depois de 30 minutos, ou na hora pelo botão "Conferir com o provedor" da T5).
- **"O provedor de pagamento recusou a cobrança" logo na primeira contribuição:** veja o terminal do Nest. Se a mensagem for "Você não possui uma chave Pix cadastrada", falta a chave Pix da conta (Parte 3, passo 4).
- **A transferência fica no Asaas como "aguardando autorização" e o repasse em "Processando":** a validação de saque (Parte 9) não está ligada, ou a URL dela é de um túnel antigo.
- **A transferência falha com "Autorização externa foi recusada":** o próprio sistema recusou. O motivo aparece no terminal do Nest numa linha `Saque RECUSADO (...)`. Se aparecer `401`, o token da validação de saque no Asaas é diferente do `whsec_...` do `.env`.
- **A transferência falha com "Pagamento rejeitado pelo PSP do recebedor":** no sandbox, é o banco fictício da chave recusando (veja "Testar o repasse ao pesquisador no sandbox", na Parte 10).
- **"A conexão caiu" ou "ECONNRESET" no meio de um teste:** o `npm run start:dev` reinicia o Nest sozinho **toda vez que um arquivo do `nest/` é salvo**. Espere ele subir de novo e repita.
- **Descobrir o endereço atual do túnel sem procurar no terminal:** abra `http://127.0.0.1:20241/quicktunnel` no navegador (com o túnel aberto).
- **O repasse fica "Aguardando chave Pix":** o dono da campanha ainda não tem chave Pix com titularidade confirmada.
- **Quero voltar para o provedor de teste:** apague a linha `PAYMENT_PROVIDER=asaas` (ou troque para `fake`) e reinicie o Nest. As outras linhas `ASAAS_...` podem ficar.

## Parte 13 - trocar de plataforma no futuro

O sistema não depende do Asaas. Ele fala com três "portas" genéricas (cobrar, transferir, receber avisos), e cada plataforma é um **adaptador** numa pasta própria (`nest/src/29-pagamento/adapters/`). Para trocar, por exemplo, pelo Mercado Pago:

1. criar `nest/src/29-pagamento/adapters/mercadopago/` com as três portas, falando a língua da API do Mercado Pago;
2. acrescentar uma linha em `nest/src/29-pagamento/pagamento.module.ts` (a função `criarAdapter`);
3. trocar `PAYMENT_PROVIDER` no `.env`.

O banco não muda: cada contribuição e cada repasse guarda qual plataforma foi usada. Antes de trocar, deixe terminar o que está em andamento na plataforma antiga (Pix pendente, devolução na fila), porque as tarefas automáticas só tratam a plataforma configurada. E confirme que a plataforma nova faz **transferência Pix para terceiros pela API**: o repasse ao pesquisador depende disso.
