# Tutorial: rodar os testes automáticos (Playwright, axe-core e banco)

Este guia explica, do zero, como rodar os testes automáticos do CrowdAcadêmico e onde ver o resultado. Não precisa decorar nada: é só copiar e colar os comandos deste arquivo, na ordem.

**O que são os testes, em poucas linhas.**

- **Playwright** (pasta `testes-e2e/`): abre um navegador sozinho e faz o que uma pessoa faria. Entra, cria conta, apoia uma campanha com Pix, aprova campanha no painel... Também chama a API direto (os casos de teste CT-01 a CT-13 do TCC), confere a acessibilidade de 22 telas com o **axe-core** (tema claro e escuro, computador e celular) e mede o tempo de resposta (CT-16).
- **Suíte do banco** (pasta `informacoes/testes-banco/`): confere as regras do banco (triggers, permissões, dinheiro), mais de 2.000 casos.

**Não mexe em nada de verdade.** Os testes sobem um banco próprio, descartável, com o seed, numa porta própria. Nunca tocam no Supabase nem no Asaas, e nenhum e-mail sai da máquina. Podem rodar com o seu Nest (3000) e o seu React (5173) ligados: usam outras portas.

---

## ❓ Preciso ligar o Nest, o React ou o túnel antes?

**Não.** Os testes sobem tudo sozinhos e desligam no fim:

| O do dia a dia | Para os testes |
|---|---|
| Nest (`npm run start:dev` ou `start:dev:teste`, porta 3000) | não precisa: os testes sobem um Nest próprio (porta 3101), já com pagamento e e-mail de teste |
| React (`npm run dev`, porta 5173) | não precisa: os testes sobem um React próprio (porta 5175) |
| Túnel (`npm run tunel`) | não precisa: o pagamento de teste não usa o Asaas nem webhook |
| Supabase | não precisa: os testes sobem um banco próprio (porta 5434) |

Se os seus estiverem ligados, tudo bem: as portas são outras, um não atrapalha o outro.

---

## ✅ O comando do dia a dia (o único que você precisa)

Abra um terminal na pasta do projeto (`crowdacademico`) e cole:

```
cd testes-e2e
npm run relatorio
```

Espere uns **10 minutos** (4 da suíte do banco e 6 do Playwright). No fim aparece:

```
Relatório gravado: ...\testes-e2e\resultados\relatorio-2026-11-16_1723.md
```

Abra esse arquivo no VS Code: tem a tabela com quantos casos passaram e falharam em cada suíte, o tempo médio do CT-16 e as violações do axe-core por tela. **É dele que saem os números para a banca.**

## 🛠️ Primeira vez num computador (só uma vez)

**Cada uma das três pastas (`nest`, `react` e `testes-e2e`) tem o próprio `package.json`**, então cada uma precisa do seu `npm ci` (ou `npm install`), uma vez por computador. Ninguém instala o Playwright "no computador": ele vem dentro do `npm ci` da pasta `testes-e2e`, junto com o Postgres de teste. A única coisa à parte é o navegador que ele usa (`npx playwright install chromium`).

### 🏫 Computador da escola, do zero (o que fazer na ordem)

**Boa notícia: os testes não precisam do Supabase.** Eles sobem o próprio banco. Então dá para testar mesmo sem acesso ao banco de verdade.

1. **Instale o Node.js (versão LTS) e o Git.** Se o computador reseta todo dia, use os instaladores guardados no Drive ou no pendrive (`.Tutorial-rodar-projeto.md`, seções "Computador que reseta todo dia" e "Parte 0").
2. **Leve o arquivo `nest/.env`** (do seu computador, pelo Drive ou pendrive). Ele não vai para o Git. Os testes leem dele só a chave do login (JWT) e as chaves do CPF; o banco, o pagamento e o e-mail são trocados pelos de teste. O `react/.env` **não** é preciso para os testes.
3. **Baixe o projeto**, abra um terminal numa pasta qualquer (ex.: Documentos) e cole:

   ```
   git clone <endereço do repositório no GitHub>
   cd crowdacademico
   ```

4. **Coloque o `nest/.env`** que você levou dentro da pasta `nest` do projeto baixado.
5. **Instale as três pastas e o navegador** (cole tudo de uma vez, de dentro da pasta `crowdacademico`):

   ```
   cd nest
   npm ci
   cd ../react
   npm ci
   cd ../testes-e2e
   npm ci
   npx playwright install chromium
   ```

   Precisa de internet: são uns 130 MB de pacotes na `testes-e2e` (o Postgres de teste vem aqui) e uns 300 MB do navegador. Leva alguns minutos. Num computador que reseta todo dia, este passo se repete a cada dia.
6. **Rode os testes** (você já está dentro de `testes-e2e`):

   ```
   npm test
   ```

   Ou `npm run relatorio`, se quiser o arquivo com os números (seção acima).

**A suíte do banco só existe na sua máquina:** a pasta `informacoes/` fica fora do Git, então ela não vem no `git clone`. Num computador sem ela, o `npm run relatorio` pula essa parte sozinho e roda só o Playwright. Para ter as duas na escola, leve também a pasta `informacoes/testes-banco` e rode `npm ci` dentro dela.

## 🎯 Rodar só uma parte (mais rápido)

Sempre de dentro da pasta `testes-e2e`:

| Quero testar... | Comando | Tempo |
|---|---|---|
| Tudo do Playwright, sem a suíte do banco | `npm test` | ~6 min |
| Só as telas | `npm run test:interface` | ~4 min |
| Só a API (CT-01 a CT-13) | `npm run test:api` | ~1 min |
| Só a acessibilidade (axe-core e celular) | `npm run test:acessibilidade` | ~5 min |
| Só o tempo de resposta (CT-16) | `npm run test:desempenho` | ~1 min |
| Só a suíte do banco | `cd ../informacoes/testes-banco` e depois `npm test` | ~4 min |

Esses comandos mostram o resultado no terminal, mas **não gravam** o relatório em `resultados/`. Para o relatório, use o `npm run relatorio`.

## 👀 Quero VER o navegador fazendo os testes

O `npm test` (e os outros comandos acima) roda com o navegador **invisível**, de propósito: é mais rápido. Enquanto ele roda, a tela não mostra navegador nenhum; no terminal aparece só uma linha por caso, com ✓ (passou) ou ✘ (falhou). **Isso é normal, não travou.**

Para **assistir**, use um destes comandos **no lugar** do `npm test` (de dentro da pasta `testes-e2e`):

| Quero... | Cole isto no lugar do `npm test` |
|---|---|
| Ver a janela do navegador fazendo os passos, só nas telas (o mais interessante de ver) | `npx playwright test --headed --project=interface` |
| Ver a janela em todos os testes (os da API não abrem janela: não usam navegador) | `npx playwright test --headed` |
| Um painel para escolher qual teste rodar, assistir e voltar passo a passo (o melhor para mostrar a alguém, como na banca) | `npx playwright test --ui` |

**Como usar o painel (`--ui`):** nada roda sozinho. À esquerda fica a lista dos roteiros; clique no ▶ ao lado de um deles para rodar só ele. No meio aparecem os passos: clique num passo para ver a tela naquele momento. O painel sobe o banco, o Nest e o React sozinho, como o `npm test`; para desligar tudo, é só fechar a janela do painel.

**⚠️ Um de cada vez.** Não abra o `--headed` nem o `--ui` enquanto um `npm test` ainda estiver rodando em outro terminal: os dois usam as mesmas portas, e o segundo dá erro de "porta ocupada" (`EADDRINUSE`). Espere o primeiro terminar (aparece "passed" ou "failed" no fim) e só então rode o outro.

**Os roteiros, por arquivo** (pasta `testes-e2e/testes/`):

| Arquivo | O que testa | Casos |
|---|---|---|
| `interface/telas.spec.ts` | as telas e os fluxos (cadastro, login, apoio com Pix, Termo novo, painel...) | 27 |
| `api/casos-de-teste.spec.ts` | os casos CT-01 a CT-13 do TCC chamando a API | 13 |
| `acessibilidade/axe.spec.ts` e `celular-ct15.spec.ts` | axe-core em 22 telas e o CT-15 no celular | 96 |
| `desempenho/ct16-tempo-de-resposta.spec.ts` | o CT-16 (tempo de resposta) | 3 |

## 🔍 Um teste falhou. E agora?

1. No terminal, o nome do teste que falhou aparece em vermelho, com a linha do erro.
2. Para ver **o que aconteceu na tela** (com foto e o passo a passo), rode:

   ```
   npx playwright show-report .estado/relatorio-html
   ```

   Abre uma página no navegador. Clique no teste vermelho: tem a foto do momento da falha e o "trace" (filme do teste, clique por clique).
3. Mande o nome do teste e a mensagem de erro para o Claude.

## ⚠️ Problemas comuns

| O que aparece | O que fazer |
|---|---|
| `Error: listen EADDRINUSE` ou "port 5175 / 3101 / 5434 is already used" | Sobrou um servidor de uma rodada anterior. Feche o terminal antigo, ou reinicie o computador, e rode de novo. |
| `Executable doesn't exist ... chromium` | Faltou instalar o navegador: `npx playwright install chromium` (dentro de `testes-e2e`). |
| `Cannot find module` | Faltou o `npm ci` de alguma das três pastas (passo 5 do "Computador da escola"). |
| O Nest não sobe e fala do `.env` | Falta o `nest/.env`. Copie do seu computador (passo 2 do "Computador da escola"). |
| Demora muito na primeira vez | Normal: está baixando o Postgres e compilando o Nest. Nas próximas é mais rápido. |

## 📁 Onde fica cada coisa

- `testes-e2e/testes/`: os roteiros (`interface/`, `api/`, `acessibilidade/`, `desempenho/`).
- `testes-e2e/resultados/`: os relatórios gravados (vão para o Git).
- `testes-e2e/.estado/`: o que cada rodada gera (banco, fotos, relatório HTML). Fica fora do Git e é apagado e refeito a cada rodada.
- `testes-e2e/README.md`: a parte técnica (portas, como o ambiente sobe, por que cada escolha).
